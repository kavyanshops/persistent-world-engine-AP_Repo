The request pipeline

  
Order matters. Each step relies on the ones above it, and any step can end the request early. Source: src/app.js and src/middleware/.

  
    
    
  1. 1 · traceStarts a per-request trace, returned as X-Middleware-Trace.
    2. 
    
  2. 2 · requestIdGives every request an id. It appears in the response, the log and every error body.
    3. 
    
  3. 3 · securityHeadersCSP, nosniff, frame deny, no-store on API replies. Hides X-Powered-By.
    4. 
    
  4. 4 · loggerWrites one JSON line per request when the response finishes, and feeds the audit log.
    5. 
    
  5. 5 · rateLimit300 requests per minute per IP. Login has its own limit: 5 per minute per IP and email. Ends with 429.
    6. 
    
  6. 6 · express.jsonParses JSON, capped at 10 kB. Bad JSON gives 400, too large gives 413.
    7. 
    
  7. 7 · authenticateVerifies the Bearer JWT: signature, algorithm, issuer, audience, expiry, revocation. Fails with 401.
    8. 
    
  8. 8 · authorize + validateChecks the role's permission (403) and the shape of params, query and body (400).
    9. 
    
  9. 9 · handler → errorHandlerRuns the parameterised SQL. Missing row 404, illegal state change 409. All errors leave through one handler.
    10. 
  

  
Which status code means what

    
401We do not know who you are
403We know you, and the answer is no
400Your request is malformed
404Nothing there
409Valid request, wrong state
429Slow down
